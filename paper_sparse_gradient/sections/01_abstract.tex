\begin{abstract}
Sparse-index gradient accumulation is a recurring operation in embedding-heavy and sparse-feature training workloads, where repeated indices route multiple gradient contributions to shared parameter rows during backpropagation. Although PyTorch exposes several semantically related CUDA paths for this pattern, API-level similarity does not imply interchangeable execution behavior. This paper characterizes three standard paths, \texttt{index\_add}, \texttt{scatter\_add}, and \texttt{Embedding.backward}, using correctness-gated benchmarks, matched sparse-index workload grids, CUDA-event timing, profiler inspection, threshold-sensitivity checks, descriptive bootstrap intervals, regret analysis, and a controlled backward-style proxy.

Across two distinct GPU/software stacks, the fastest path depends on workload shape, timing scope, and execution stack. The matched isolated benchmark and the backward-style proxy do not yield the same ranking, showing that isolated accumulation results should not be transferred mechanically to broader backpropagation-style computation. Profiler summaries further show that the three paths use distinct CUDA execution-path compositions, including direct accumulation kernels for the tensor APIs and a multi-kernel embedding backward path with sorting or segmentation-related components. These findings make sparse-index gradient accumulation a systems-level backpropagation concern rather than a purely semantic API choice.

The analysis also shows why a tie-aware interpretation is needed. Practical-margin threshold checks and winner maps reveal workload regions with decisive winners and regions dominated by near-ties, while regret analysis shows that static API selection can still be costly. The lowest-mean-regret static choice varies by stack and scope, and the smallest observed worst-case static regret still reaches 145.0\%, precluding a safe universal default. The practical output is therefore not a universal ranking of \texttt{index\_add}, \texttt{scatter\_add}, and \texttt{Embedding.backward}, but a measurement-backed, tie-aware selection protocol: measure candidate paths under the target sparse workload and execution stack, treat small differences as practical ties, validate isolated rankings against a broader backward-style scope when relevant, and use profiler evidence to inspect execution-path divergence.
\end{abstract}

\noindent\textbf{Keywords:} sparse gradients; sparse-index accumulation; backpropagation; PyTorch; CUDA; embedding backward; index add; scatter add; AI model training
